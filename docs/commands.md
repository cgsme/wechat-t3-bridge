## 使用

- `/stop`：向当前线程提交停止请求，并取消该线程在桥接中的排队任务。用 `/status` 核对结果。
- `/to 2 /stop`：停止最近一次线程列表中的第 2 个线程，不改变当前选择。请勿省略 `/`。

技能参数 `--skills` 与 `--skill` 等价，例如 `/task --skills code-review,tdd 审查并修复代码`。

- `/skills [关键词]`、`/技能 [关键词]`：查询本机用户技能及桥接配置工作目录下 `.agents/skills` 的技能（不包含插件动态注入的技能）。
- `/task --skill code-review 审查代码`：校验技能名称后，将技能文件位置及使用指令传给 T3；实际执行由目标线程的助手完成。
- `/new --skill tdd --name 修复任务 修复问题`：在新线程中使用技能；`--skill` 须紧跟 `/task` 或 `/new`，多个技能用英文逗号分隔。也支持 `/to 2 /task --skill tdd 修复问题`。普通正文中的 `$技能名` 会原样传给 T3。

- 直接发送文字：默认在当前选中的线程执行任务，正文直接交给 T3。
- `/task <request>`：直接发送文字的可选写法，行为完全相同。
- `/steer <补充指令>`、`/引导 <补充指令>`：立即引导当前线程正在运行的任务；也支持 `/task --steer <补充指令>`。
- `/to 2 /steer <补充指令>`：引导指定线程，不改变当前选择。引导会绕过桥接的普通任务队列，立即返回送达状态；任务结果可用 `/history` 或 `/to 2 /history` 查看。T3 如果启动了新任务或将消息排队，回执会如实说明。待答问题请用 `/answer`，权限确认仍在 T3 处理。
- `/to <number|id|prefix|home> <request>`：向指定线程发送任务，不改变当前选中线程；编号沿用最近一次 `/threads` 列表。
- `/new <request>`：先回复“正在创建”，核实创建并选中独立任务线程后立即返回确认、线程序号、线程名和短 ID，任务结果稍后单独返回。
- `/new --name <名称> <request>`：为新线程指定名称；也支持 `--title`、`--名称`、`--名字` 和 `-n`，`/n`、`/新建`、`/新线程` 同样支持。
- `/new --project <编号|名称|ID前缀|home> [--name <名称>] <request>`：同时指定项目和可选名称；项目参数也支持 `--项目`、`-p`，项目与名称参数可任意排序。
- `/projects`：列出 T3 项目及编号，标记当前项目。
- `/project`：查看当前选择的项目；后续 `/new` 的线程属于该项目。
- `/project <编号|名称|ID前缀|home>`：选择项目，`home` 返回最初绑定的项目。
- `/threads`：列出当前 T3 项目未 settle 的可用线程及编号。
- `/threads --settle`：包含已 settle 的线程，并标记其状态；`/t --settle`、`/ts --settle`、`/线程 --settle` 同样可用。
- `/settle [编号|ID|前缀|home]`：收起指定线程；省略目标时操作当前线程。
- `/unsettle [编号|ID|前缀|home]`：恢复显示指定线程。也支持 `/to 2 /settle`、`/to 2 /unsettle`，操作不切换当前线程。
- `/history [页码]`：查看当前线程的对话历史，默认最近 5 条；`/history 2` 查看更早一页。
- `/to 2 /history [页码]`：查看指定线程的对话历史，不改变当前选中线程。
- `/switch <number|id|prefix|home>`：按上次列表的编号、完整 ID、唯一 ID 前缀切换线程；`home` 返回最初绑定的线程。
- `/models [search]`：从 T3 实时读取模型目录；可加关键词搜索被摘要省略的模型。
- `/model`：查看所选线程的提供商、模型和推理等选项。
- `/model <number>`、`/模型 <序号>`、`/m <number>`：按当前线程最近一次模型列表的序号切换模型，也支持 `#2` 写法。
- `/model <model>`：切换所选线程的模型；优先在当前提供商内匹配完整模型 ID。
- `/model <provider>::<model>`：明确指定提供商及模型，适合重名或跨提供商切换。
- `/fast`：查看当前选中线程的 Fast 状态。
- `/fast on`、`/fast off`：开启或关闭当前线程的 Fast 模式。
- `/to <number|id|prefix|home> /fast [on|off]`：查询、开启或关闭指定线程的 Fast，不改变当前选中线程。
- `/to <number|id|prefix|home> /status`：查看指定线程的状态及 Fast 状态。
- `/questions`：查看当前线程待补充的问题，重启后也可重新读取。
- `/answer <文字|编号>`：回答已显示的问题；也可以直接回复文字或选项编号。多选用逗号分隔，例如 `/answer 1,2`；多题逐项回答。
- `/status`：检查微信连接、当前选中线程、Fast 状态及排队数量。
- `/cost [today|7d|30d]`、`/费用 [今天|7天|30天]`：查看本机 T3 用量面板的费用汇总，默认今天。
- `/token [today|7d|30d]`、`/tokens`、`/用量`：查看 Token 汇总和当前线程上下文用量。
- `/limit`、`/额度`：查看提供商及外部额度源的账户使用比例、剩余比例和重置时间。
- `/help`：默认显示中文帮助；每条先列命令与参数，再在下一行缩进说明用途，类似命令手册。
- `/help en`：以相同格式显示英文帮助；仅对本次帮助生效。

命令支持英文、短别名和中文，均使用 `/` 前缀，也兼容全角 `／`。`/ping`、`/start` 不作为别名。任务内容可使用中文。例如直接发送 `检查本机内存`，或发送 `/新建 检查本机内存` 新建线程处理。使用编号切换前，先发 `/threads`、`/t` 或 `/线程`；编号始终对应最近一次返回的列表。

别名不区分大小写，参数及行为与完整命令一致，帮助会在完整命令旁列出别名。`/to` 已是短命令，保持原写法。定向用法也支持别名，例如 `/to 2 /f on`、`/to 2 /a 1`；`/n /ts`、`/tk /t` 等包在任务命令中的控制别名会直接执行。只展开命令开头的完整单词，不改写任务正文中的文字；无 `/` 的 `t` 或 `ts` 仍作为普通任务内容。

中文命令支持相同参数及定向用法，例如 `/发送 2 /快速 开启`、`/发送 2 /回答 1`、`/发送 2 /状态`。Fast 支持“开启/启用/打开/开”和“关闭/禁用/关”；`home` 可写“初始”，如 `/切换 初始`、`/项目 初始`、`/发送 初始 检查内存`。“初始”作为保留参数表示最初绑定的线程或项目。`/帮助 英文` 查看英文帮助，`/帮助 中文` 查看中文帮助。命令与参数之间支持普通空格和全角空格；没有 `/` 的中文仍作为任务正文。中文帮助列出中文别名，英文帮助保持英文。

选择新线程所属项目时，依次发送 `/projects`、`/project 2`、`/new 具体要求`。也支持完整项目名称，例如 `/project Empty Project`，或项目 ID 的唯一前缀。项目编号对应最近一次 `/projects` 返回的列表，与线程编号分开保存。切换项目会恢复该项目上次选中的可用线程和已保存的线程编号，首次进入时选中列表中的首个可用线程；`/threads`、`/switch`、`/to` 随后作用于选中的项目。`/switch home` 返回最初绑定的线程及其项目，`/to home` 则向该线程定向发送。

也可一条命令完成，例如 `/new --project 2 --name "Weekly Report" 整理本周报告`，或 `/新建 --项目 "Empty Project" --名称 内存检查 检查内存`。`--project` / `--项目` / `-p` 支持项目编号、完整名称、ID 或唯一 ID 前缀，`home`（或 `初始`）指最初绑定的项目；编号使用最近一次 `/projects` 的映射。含空格的项目名称与线程名称均需用引号包住，也支持 `--project=2`；所有参数放在任务正文前，顺序不限。正文以参数形式开头时，用 `--` 分隔，如 `/new -p 2 -- --name 是任务正文`。模型沿用命令执行时当前线程的模型，当前项目为空时沿用此前的模型来源。先验证目标项目并创建，确认新线程属于目标项目后才切换当前项目及线程；出错时保留当前选择，创建结果不确定时不自动重试。切换后继续保留原项目的选中线程和编号，新线程确认及回复使用目标项目内的线程序号。

空项目可以直接用 `/new <要求>` 创建首个任务线程，模型继承切换前选中的线程；之后继承当前线程的模型。创建的线程使用目标项目的工作目录。项目选择与每个项目上次选中的线程会持久保存；已排队或正在执行的任务固定所属项目和线程，切换项目后继续在原处执行。项目选择不会移动已有线程。

例如 `/to 2 检查本机内存` 将任务发给上次列表的第 2 个线程，`/to mcp:abc 继续整理报告` 使用完整 ID 或唯一前缀，`/to home 检查磁盘` 发给最初绑定的线程。目标在分派时固定并持久保存，后续切换线程或刷新列表不会改变已排队任务的目标；不会创建新线程。不同线程仍可并发，同一线程内定向任务和普通任务共用顺序队列。无效编号、歧义前缀、已归档或项目外线程会直接报错，不会回退到当前线程执行。

也可用 `/to 2 /questions` 查看指定线程的问题，或 `/to 2 /answer 1` 定向回答，不必先切换。已显示的问题也能用 `/to 2 <答案>` 回答，沿用现有的问题核对和失效保护。`/to` 内接受任务、`/questions`、`/answer`、`/fast [on|off]` 和 `/status`，不执行切换、新建线程或模型变更等其他控制命令。`/switch` 与 `/to` 均支持含 `mcp:` 的完整线程 ID。

补充问题会显示 `线程序号：#2`，并给出可直接使用的定向回答和查看命令，例如 `/to 2 /answer 1`。未列入列表的线程追加编号，不改变已有编号。多题后续提示和重新查看问题时会按最新列表重新计算序号。其他项目的后台线程使用所属项目的编号，先提示选择所属项目，并用短 ID 生成定向命令，避免把当前项目的编号用于旧项目。刷新 `/threads` 后，以新列表的序号为准。

`/fast on` 只设置当前选中线程；`/to 2 /fast on` 则只设置上次列表的第 2 个线程，`/to 2 /fast off` 关闭，`/to 2 /fast` 或 `/to 2 /status` 查看实际状态。定向查询及设置的回复携带目标线程标识，不改变所选线程或列表编号。Fast 控制与 `/status` 直接执行，不等待目标线程已有的长任务结束，Fast 设置用于后续任务，正在运行的任务不会重启。定向 `/status` 的线程信息和 Fast 属于目标线程，任务计数仍是整个桥接队列的统计。

查询结果使用适合微信的纯文本分块排版：`/threads` 按条目展示 `#序号 线程名（短ID）` 和中文状态，`⭐ 当前` 标记选中线程；`/status` 分开显示连接状态与任务队列；`/models` 按提供商分组并标记当前模型，`/model` 单独展示模型与选项。帮助按任务、线程、模型和提问分区，待答问题将题目、选项和回答方法分开。长回复优先在条目或行末分段，每段保留线程标识和原始提问摘要。

`/new /threads`、`/task /threads` 等包在任务命令中的完整桥接控制命令，也由桥接直接执行，不创建线程、不发送给 AI。这样列表显示的编号与 `/switch` 保存的映射一致。只有桥接 `/threads` 返回的编号可用于切换；AI 在普通任务回复中自行列出的编号不作为切换编号。新建线程或服务器重新排序不会改变上次列表的编号。

当前选中项目和线程会持久保存，重启后继续使用。`/new` 使用所选线程的 provider 和 model，在选中的 T3 项目中创建线程；工作目录和权限由 T3 的新线程默认设置决定。线程创建不会复制旧线程的历史消息。创建并选中后就释放命令队列，首次任务在后台运行；可以连续发送 `/new`，不同线程的任务并发执行，不设并发数量上限。单个线程内的任务按顺序执行。Agent 的补充问题会转发到微信，回答后继续原任务；权限确认仍在 T3 桌面端处理。

例如 `/新建 --名称 内存检查 检查本机内存` 或 `/new --name "Weekly Report" 整理本周报告`。名称包含空格时使用单引号、双引号、中文弯引号或 `「」` 包住，也支持 `--name=名称`。名称必须是非空单行文字，后面需要跟任务内容；不完整的参数会返回用法，不创建线程。指定名称作为 T3 的 `--title` 参数传递，不添加 `WeChat:` 前缀、不截短；首次任务只接收名称参数之后的正文。未指定名称时继续按任务首行自动命名。排队任务的名称与正文一同持久保存，创建确认及后续结果使用实际读取的线程名称。

还有任务排队或执行时，桥接通过微信 `sendtyping` 接口发送“正在输入”状态，每 5 秒刷新。每 5 秒检查初始项目、选中项目及已访问项目的可用顶层线程，因此从桌面端启动的后台任务及桥接重启后仍在执行的任务也能保持提示。切换所选线程或其中一个任务完成，不会取消其他任务的输入状态；所有任务结束后取消。发出回复后会重新刷新，以继续提示其他运行任务。输入状态请求和任务执行互不等待，接口失败时自动重试，ticket 仅保存在内存中。状态文件中的 `typing` 表示最近成功提交的状态，`typingError` 和 `activityError` 分别记录输入状态及线程查询失败；手机实际显示由微信客户端决定。

模型命令由桥接直接处理，不发送给 AI 猜测或代改配置。例如先发送 `/模型列表`，再发送 `/模型 2` 选择列表中的第 2 个模型；也可发送 `/models gpt` 搜索，再复制模型 ID 发送 `/model gpt-6.1-sol`。只有所选线程的模型会改变，后续消息和任务使用新模型；已开始的任务不会重新执行。同提供商切换会保留目标模型支持的现有选项；不兼容的选项或跨提供商切换使用 T3 默认值。切换线程后 `/model` 查询对应线程的实际配置。T3 会保存模型选择，重启桥接后仍可读取。

模型列表按提供商分组，序号在所有分组中连续递增。每个线程分别保存最近一次查询或搜索返回的“序号 → 提供商＋模型”映射，重启桥接后仍有效。切换时按保存的完整条目重新校验可用性，不依赖服务端当前排序，也不按重名模型猜选其他提供商。重新查询或搜索会更新该线程的编号；空结果会清空旧编号，失败的查询保留原列表。未查询、无效或越界序号会提示先发送 `/models`；模型失效或提供商禁用时不会切换到其他模型。完整模型 ID 和 `provider::model` 用法继续可用，纯数字模型 ID 可用 `provider::数字ID` 明确指定。

模型目录来自本机 T3；已禁用的提供商会被过滤，目录条目是否能实际推理还取决于提供商登录、账户权限和网络。重名时不会猜选其他提供商，会提示使用 `provider::model`。模型变更后读取 T3 配置核对，再回复成功。

Fast 使用本机 T3 模型目录提供的 `serviceTier` 选项：开启对应 `priority`，关闭对应 `default`。只在所选模型明确支持这两个值时允许切换，保持同一提供商、模型、推理强度及其他选项，写入后重新读取核实。设置按线程保存，后续任务使用新设置，已有任务不会重启；`/new` 仍按原有规则只复制提供商和模型，不复制模型选项。`/status` 和 `/fast` 均实时读取 T3，而非使用桥接缓存；状态会区分已开启、已关闭、不支持和读取失败，读取失败时 `/status` 的连接及任务队列仍可显示。`/fast` 与模型控制一样由桥接直接执行，不作为任务正文交给 AI；`/task /fast on`、`/new /fast on` 也直接处理，不创建线程。

文字和已包含转写文本的语音可以使用。图片、文件和未转写语音暂不处理。所有正文默认作为任务进入所选线程，`/task` 仅为可选前缀，桥接不附加额外提示词；`/task`、`/new` 解析后只转发命令中的正文。回复行为由 T3 线程已有的指令和权限决定。

历史查询直接读取 T3 中的用户与助手文字，不启动任务，也不写入对话。每页最多 5 条，页内按先后顺序展示，长消息自动分段并保留线程标识。页码范围为 1–100（最近最多 500 条记录）；新消息到达后分页随最新记录变化。工具调用、系统内容和附件二进制不显示。查询只允许当前项目中未归档的顶层线程（`/to home /history` 可查看初始线程）；指定线程查询不会改变线程列表编号或待答问题。`/to` 也支持 `/history` 查询。

回复中的线程序号、项目序号、问题及选项序号、历史页码使用数字 emoji，例如 1️⃣、2️⃣、1️⃣0️⃣，配合留白分块展示。可复制的命令示例和输入仍使用普通数字，如 `/switch 2`、`/answer 1`、`/history 2`；编号与实际目标的对应关系不变。对话正文、模型 ID 和参数值保留原文。

settle/unsettle 通过 T3 的线程整理接口处理，不作为任务发送给 AI，不停止任务、不归档线程。编号沿用最近一次 `/threads` 或 `/threads --settle` 的列表；操作本身不刷新或重排列表。恢复隐藏线程前可先用 `/threads --settle` 列出，也可使用完整 ID 或唯一前缀。写入后重新读取实际状态，再报告成功；状态未确认时明确提示核对，不自动重试。目标必须为当前项目中未归档的顶层线程，`home` 指向初始线程。

## 用量、费用与额度

`/cost`、`/token` 的费用和 Token 汇总与本机 T3 用量面板使用同一个 `server.getUsageSummary` 接口，范围是面板扫描到的全部本机来源，包含其他线程和原生 CLI 记录，不是当前线程的独占统计。默认按电脑时区统计今天，可用 `7d`、`30d` 或 `7天`、`30天` 查询包含今天在内的近 7、30 个日历日。`/token` 另外读取当前线程的活动提供商上下文快照，显示已用、上限及占用比例；`/to 2 /token` 或 `/发送 2 /用量` 查看指定线程的上下文，总量部分仍为本机统计。空项目也可读取面板汇总及账户额度，不会为查询创建线程。

Token 输入总量包含普通输入、缓存读取和缓存写入；推理 Token 已计入输出，不重复相加。费用使用 T3 返回的提供商报告值或模型定价估算，以美元显示，不能当成实际账单；未定价记录、数据源部分失败、缓存定价和后台刷新都会单独标注。提供商未报告上下文数据时显示“未提供”，不以零替代。

`/limit` 使用 T3 提供商快照与外部额度源快照，按账户窗口展示已用、剩余百分比、重置时间及快照时间。额度属于提供商账户，多线程可能共用；星号标记当前线程使用的提供商。读取失败时标明旧快照，不支持或无数据时明确显示，外部源不可用时保留已读取的提供商快照。`/to 2 /limit` 可以针对目标线程标记其提供商，账户额度本身仍共享。此命令只读取可用重置额度数量，不使用重置额度。

查询经 T3 本地回环 WebSocket 接口完成。每次用本地 CLI 签发两分钟的 `orchestration:read` 和 `diagnostics:read` 凭据，申请专用连接票据，结束后关闭连接并撤销凭据。读取接口限定为用量汇总、提供商快照和线程快照；不访问未授权的远程服务，不更改模型或运行任务，凭据、账户鉴权数据和服务端原始错误不写入消息或日志。

## 引用消息定位线程

更新后，长按桥接的一条新回复并选择“引用”，再输入任务正文、`/history`、`/answer 2`、`/fast` 等线程指令，就会发回原线程，不改变当前选中线程或项目。引用自己先前发给该线程的任务也可定位。显式指定目标（如 `/to 2 <要求>`、`/settle 2`）优先；`/new`、`/switch`、`/project`、`/threads`、`/help` 等全局命令保持各自语义。

桥接使用微信 `ref_msg.svr_id` 与发送响应 `message_id` 建立映射；客户端只传回完整引用文字时，以已保存内容的精确哈希匹配。映射保留完整 T3 线程及项目 ID，不依赖易变化的显示序号，重启后仍有效。记录按绑定账号隔离，保留最近 30 天、最多 2000 条，不额外保存引用原文。消息 ID 按原始数字保真解析，避免 uint64 被 JavaScript 舍入后无法关联。

更新前的旧消息、未保存或过期的引用、只含无法匹配的片段、含多个不同线程的引用，不能保证识别。无法唯一定位或目标不可用时会明确提示使用 `/to`，不会退回当前线程执行。线程列表、项目列表、帮助及“正在创建”回执不作为引用定位依据；引用原文不会拼接到任务指令。手机实际是否携带引用字段，仍需用当前微信客户端验证。

协议依据：[腾讯消息类型](https://github.com/Tencent/openclaw-weixin/blob/main/src/api/types.ts)、[腾讯发送端保存服务端消息 ID 的实现](https://github.com/Tencent/openclaw-weixin/blob/main/src/messaging/send.ts)。

## 完整 HTML 回复

模型回复中的本地 `.html`/`.htm` 报告链接、HTML 代码块和同一任务内的 T3 `html_render` 页面，会以“文字说明＋完整 HTML 文件附件”发到微信。桥接保留原始页面字节、样式和脚本，不渲染或执行 HTML；下载后用浏览器打开，微信聊天气泡及内置预览不保证支持交互脚本。依赖远程资源的页面需要联网；相对路径引用的本机图片、CSS 等资源不会自动打包。

本地链接只读取任务目录、T3 scratch/附件目录或系统临时报告目录中的 HTML；每个回复最多 5 个附件、每个最大 5 MB。HTTP 网页链接保持原样，不自动抓取。T3 内嵌页面按线程和任务 run ID 提取，避免发送旧任务页面。普通文字回复不变；附件准备失败时保留原回复并说明原因。附件发送与文字分开持久记录进度，失败后重试附件，不重跑模型任务；图片、HTML 文件均不会在桥接中执行。HTML 附件的微信消息 ID 也会记录，引用新附件可定位原线程。

微信文件发送按照[腾讯上传实现](https://github.com/Tencent/openclaw-weixin/blob/main/src/cdn/upload.ts)与[文件消息结构](https://github.com/Tencent/openclaw-weixin/blob/main/src/messaging/send.ts)，使用 AES-128-ECB 加密后上传微信 CDN，并发送 FILE 类型附件。仅向绑定微信账号回传模型生成的报告，不发布到网页。
